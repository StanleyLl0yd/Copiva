## Scope and method

First complete pass: all48 tracked blobs at `9d89fbe4b701c9f7bbf1b0118301b1460e436879` (PR#12 candidate), fetched by GitHub API without a repository checkout. These absent surfaces are not claimed as tested.

## Preservation and simplification decisions

- Removed no production feature, public enum case, resource, regression test or compatibility path. The complete48-file first pass found no proven dead subsystem worth deleting.
- Kept framework entry points: SwiftUI App/body/scenes, NSView key handling, NSWindowDelegate callbacks, Carbon C handler and pasteboard provider callbacks. Textual lack of callers does not make them dead.
- Kept public AppInfo/PasteMode serialization and immutable0.0.1 release/tag/assets. No canonical artwork exists; the provisional menu symbol is unchanged.
- Kept CopivaCore and CopivaMac boundaries: storage tests need no AppKit, while named-pasteboard/Carbon tests and UI share platform adapters. No speculative service/repository layer added.
- Kept independent validation at publication's artifact/identity boundary. Reduced actual duplicate request-policy logic to one small standard-library module with fail-closed tests; this is not a new external dependency.
- Kept SQLite transactions, WAL/FULL sync, FTS triggers and stable IDs. Schema1 has no pins; future pinning must migrate and change retention deliberately.
- Kept a conservative AX writable/non-secure text-field policy. Unsupported apps use Copy; broadening paste support without real-Mac proof is deferred.
- No benchmark, forensic deletion, encrypted storage, universal paste support, pre-allocation read bound, notarization or independent-human-review claim is made.

## Second complete pass and remaining gates

A fresh second pass fetched all52 blobs at4cf9ed6dd7e12374f5c99368bf03b7785027c419, including unchanged source, tests, policies, historical reports and all new release-policy files. It found M1-05 (Medium): explicit macOS pasteboard denial was indistinguishable from an unavailable data item, leaving recording apparently active, and architecture prose understated the OS access policy. Apple documents accessBehavior/default/ask/alwaysDeny. Remediation stops capture before payload access on alwaysDeny and explains System Settings/resume; a synthetic permission-query test asserts the real named-pasteboard data provider is never called while denied. App consent text/manual QA and architecture references are corrected. Shortcut recorder is now explicitly an accessibility text-field element with a waiting value, rather than a label on an otherwise generic NSView.

After those corrections, a further complete pass re-fetched all52 files at7544c48ce8dfde4a19e8db911457ffb7244c1d21, reviewed unchanged sources/tests/config/docs and every new file, and revisited actor ownership, C callback lifetime, SQL/FTS and filesystem failure paths, sensitive marker/provider ordering, data bounds, focus/event/clipboard race limits, UI entry points, bundle/resources, dependency/license/Action pins, release intent and verification, documentation and available settings. The warning-only fixture correction, roadmap acceptance wording and this final record update were then reviewed explicitly. Added a focused packaged-process launch probe on the disposable Actions Mac with recording/consent forced off through Cocoa argument defaults, no application output collected, and cleanup restricted to the exact child process. This does not establish menu visibility, target-app focus, permissions or actual paste behavior. The new53-file candidate must be re-read/reviewed and verified before protected merge. These are separate complete static passes by the same agent, not independent human reviews.

No additional proven dead component, safe consolidation or worthwhile optimization was found. Framework callbacks, public contracts, projected UI state and the platform/core boundary remain necessary. Actor-owned synchronous SQLite calls, bounded results and one capture loop avoid an unbounded capture queue; OS pasteboard-provider waiting/allocation cannot be made a hard preallocation guarantee by the current API and remains disclosed. Actual UI, AX focus and insertion are still runtime gates. Final protected-head/main tests and scans must be observed after integration; a static audit is not milestone acceptance.
